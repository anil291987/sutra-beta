SwiftUI live preview

See a view beside its code as you type. Click an element in the preview to select its code, and ask AI to change just that element.

Try it

  1. Open a SwiftUI file and press Preview in the editor's toolbar.
  2. Pick the view and the device at the top of the pane; Real (macOS) renders it with the real SwiftUI.
  3. Click an element in the preview: its code is selected in the editor.
  4. Describe a change in the box under the preview. The edit opens as a diff with before and after renders.

Swift playgrounds

Xcode-compatible .playground files, with each line's value beside it and print() output in a console.

Try it

  1. Open a .playground (or File › New Swift Playground).
  2. It runs as you type; hover a value to see every time a loop produced it.
  3. Compile errors show on their line; pages that import UIKit run in the iOS Simulator.

Run on iPhone with xtool

Build, sign and install SwiftPM apps on a connected iPhone with xtool, on macOS, Linux or Windows (WSL). A free Apple ID works.

Try it

  1. Open Devices & Tools: connect an iPhone, sign in to your Apple account, and install the Darwin SDK.
  2. The Signing card shows your team, whether it's a free account, and how long the app's profile has left.
  3. Press Run: Sutra builds, signs and installs the app on the iPhone.

Signing Doctor

When an iPhone run fails to sign, install or launch, Sutra says why in plain words and offers the fix.

Try it

  1. Run the app. If it fails on signing, a report opens above the Output.
  2. Each finding explains the problem, lists the steps, and shows the output line it's based on.
  3. Press its button to fix it: sign in, run again, or open the right file.
  4. Tools › Check iOS Signing checks the project at any time.

App Store readiness

Find what App Store Connect or App Review would reject before you upload: missing purpose strings, the privacy manifest, export compliance.

Try it

  1. Run Tools › Check App Store Readiness (or App Store Check on the Signing card).
  2. Each finding shows the lines of code it's based on; click one to open it.
  3. Create Privacy Manifest… writes a draft declaring the API categories your app uses. You pick the reasons.

Debug Xcode projects

Breakpoints, stepping, variables and a console for Swift apps in Xcode projects, on the iOS Simulator or as Mac apps.

Try it

  1. Open an Xcode project and click the margin to set a breakpoint.
  2. Press Debug: Sutra builds, launches and attaches lldb.
  3. When it stops, read the call stack and variables, and evaluate expressions in the console.

Signing for Xcode projects

Check an Xcode project's signing for iPhone builds and archives: teams, profiles, certificates and entitlements.

Try it

  1. Open Devices & Tools: the Signing card lists each app target's team, signing style and profile.
  2. Check Signing finds what would fail, from free-team limits to expired certificates.
